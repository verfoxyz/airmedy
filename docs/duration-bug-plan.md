# 计划：修复「歌词信息里时长显示 0:01」

> 状态：待开工
> 影响面：仅**歌词信息面板**的时长显示；播放进度与文件属性中的时长正常。
> 硬约束：**AI 不做图形化测试**；界面确认由人工完成。

---

## 1. 现象

- 某首下载曲目（`前前前世 (movie ver.)`）在歌词信息里显示 `0:01`。
- 同一首歌播放时进度正常、文件属性里的时长也正常（约 4:44）。

## 2. 根因（已核实数据）

库里该行的 `tracks.duration = 1`：

```
select title, duration from tracks where id like 'b9c0d2a3%';
前前前世 (movie ver.) | 1
```

而文件本身是 284 秒（`ffprobe` 读数），播放器用**解码器**报告的时长，所以播放正常；
歌词面板读的是**库里这一列**，于是显示 0:01。

这一列为什么会是 1：

1. 下载收尾时用 taglib 读容器属性写回 `tracks.duration`（`app/download/service.go` 的
   `applyDecodedDuration`）。
2. 该文件是**旧版打标写坏的 FLAC**（ID3v2 帧写进了音频流中间），taglib 在这种容器上
   读出的时长是错的（约 1 秒）。
3. 这个错误值直接覆盖了建行时来自搜索结果、本来正确的时长。

> 结论：**写入侧缺少合理性校验**。同样的问题会出现在任何"容器损坏/非标准"的文件上，
> 不只是这一首。

## 3. 修复方案（三层，按顺序）

### A. 写入侧：不合理时长不得覆盖已有值（必须）

在 `applyDecodedDuration` 落库前判断：

- 解码时长 `<= 0` → 保留原值；
- 解码时长 `< 2s` 而原值 `>= 5s` → 保留原值，并记一条 `warn`（带 track_id、两个值）；
- 其余正常写入。

理由：一秒的歌几乎不存在；出现就说明容器读取失败，此时搜索结果的时长比"1 秒"可信。

### B. 展示侧：播放中用解码时长兜底（建议）

歌词面板/播放器信息在**正在播放**时优先使用播放器当前的解码时长，
不在播放时回落到 `tracks.duration`。这样即使某行数据仍然错误，用户看到的时间也是对的。

### C. 历史数据：一次性修复（必须）

- 新增一个**用户可触发**的修复动作（设置页或右键）：对 `duration <= 1` 且有本地文件的曲目，
  重新读一次容器属性并更新；读不出来的（容器已损坏）标记为"文件异常"，提示重新下载。
- **不做**启动时全库重算：库大、网络盘路径慢，启动会被拖住。

## 4. 边界情况

| 情况 | 处理 |
|---|---|
| 文件已损坏（旧版打标写坏） | 修复读不出正确时长 → 提示重新下载；损坏文件不能靠改数据救回 |
| 曲目本来是 1 秒的真实短音频 | 原值也 < 5s，规则 A 不触发，按解码值写入 |
| 远程曲目（尚未下载） | 不参与修复（没有文件可读） |

## 5. 估时

| 任务 | 估时 |
|---|---|
| A 写入侧校验 + 单测（正常值 / 0 / 1 秒 / 无原值） | 0.5 天 |
| B 展示侧兜底 + 组件测试 | 0.5 天 |
| C 修复动作（后端用例 + 入口 + 12 locale） | 0.5 天 |

**合计约 1.5 天。**

## 6. 验收

**自动**

- 单测：`applyDecodedDuration` 在解码值 1 秒、原值 284 秒时保持 284；
- 单测：修复动作对可读文件更新成功、对不可读文件返回明确错误；
- `golangci-lint` / `gofmt` / 前端 vitest 全绿。

**人工（由人做）**

1. 打开那首歌的歌词信息：时长不再是 0:01；
2. 播放中面板时长与播放器一致；
3. 触发"修复时长"后，库里该行变成 284；
4. 对一首真实 1 秒的音频（可造一个）不会被改坏。

**只读校验命令**

```bash
sqlite3 -readonly "%LOCALAPPDATA%/airmedy/airmedy.db" \
  "select id, title, duration from tracks where duration<=1;"
ffprobe -v error -show_entries format=duration -of default=nw=1 "<file>"
```

## 7. 不做

- 把时长判断放到播放器里（播放器已经是对的，改它只会掩盖数据问题）；
- 启动时全库重建时长；
- 为损坏文件做音频修复（做不到，只能重新下载）。
