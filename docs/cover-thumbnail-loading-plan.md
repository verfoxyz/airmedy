# 需求：云端搜索缩略图 —— 只加载可见行 + 限速

> 状态：待开工
> 范围：`frontend/src/components/catalog/CatalogResults.vue`
> 硬约束：AI 不做图形化测试；网络行为需人工在开发者工具里确认。

---

## 1. 现状与问题

现在每行是 `<img loading="lazy">`。原生懒加载只是一个**提示**：Chromium 会按"距离视口还有
一大段"就提前加载（默认约 1250px），结果是一页 50 行里可能有 20–30 张图同时发请求，
慢网下互相抢带宽，首屏文字反而更慢。

要求变成**确定性**的：

- 只加载**真正可见**的行（加一点预取边界）；
- 同时加载的图片数量有上限；
- 快速滚动时不堆积请求，滚过去又滚回来的不重复请求。

---

## 2. 方案

### 2.1 可见性：IntersectionObserver

- 用一个 `IntersectionObserver` 观察所有未加载的缩略图容器，`root` 为列表滚动容器，
  `rootMargin: '200px 0px'`（提前 200px 预取，滚动时不至于一片空白）；
- 元素进入视野 → 交给加载队列；
- 进入队列后 `unobserve`，不再重复触发；
- `rows` 变化时（新一页/换源）重建观察集合；组件卸载时 `disconnect()`。

### 2.2 限速：并发上限队列

- 同时最多 **4 张**在加载（`Image` 预加载或直接设 `src` 后等 `load`/`error`，二选一，
  推荐用 `new Image()` 预热再赋值，避免半张图闪烁）；
- 队列按进入视野的顺序处理（FIFO），不做优先级排序；
- 失败（`onerror`）不再重试，直接标记该行封面失败、显示占位图；
- 所有在途请求在组件卸载时通过取消/丢弃回调整理，避免 `setState on unmounted`。

### 2.3 占位与视觉

| 状态 | 表现 |
|---|---|
| 未加载 | 40×40 圆角块，主题 token 底色 + 音符图标（`bg-foreground/[0.06]` 级别，禁止白/黑透明度叠加） |
| 加载中 | 保持占位，不显示骨架动画（列表滚动时闪烁很吵） |
| 加载完成 | 淡入 150ms（`opacity` 过渡，用 token 时长） |
| 失败 | 保持占位图，不显示破图 |

固定 40×40 尺寸，任何状态都不改变行高——避免滚动时布局跳动。

### 2.4 不做的事

- **不做图片本地缓存**（这是缩略图，重复访问的收益抵不上复杂度）；
- **不做预取下一页**（用户没滚到就不该请求）；
- 不改后端：缩略参数仍由插件拼（`?param=100y100`）。

## 4. 验收

**自动**

- 组件测试：模拟 `IntersectionObserver`，断言未进入视野的行不设置 `src`；
- 组件测试：进入视野后设置 `src`，一次 `unobserve` 不重复触发；
- 组件测试：`error` 事件后该行进入失败态并渲染占位；
- 组件测试：卸载时 `disconnect` 被调用、队列被清空；
- 并发测试：同时可见 10 行时，在途图片数不超过 4。

**人工（由人做，AI 不做）**

1. 云端搜索一页 50 条：打开开发者工具 Network，**只应看到约 4–6 个图片请求**，不是 50 个；
2. 向下滚动：新进入视野的行才开始发请求，且同时不超过 4 个；
3. 快速滚到底再滚回顶部：已加载的图不再重复请求；
4. 断网/图床失败：占位图正常，不出现破图；
5. 亮/暗/黑三主题下占位块与列表背景对比正常。

---

## 5. 风险

| 风险 | 应对 |
|---|---|
| `root` 用错导致永远不触发 | 观察器必须挂在列表的滚动容器上，不是 `window` |
| 行复用（如果以后上虚拟滚动） | 虚拟滚动复用时需要按 key 重置状态，本轮的实现要预留 `key` 依赖 |
| 限速太严导致滚动时空白 | 并发 4 + 200px 预取；实测偏慢再调 |
| 内存泄漏 | 观察器 `disconnect`、队列清空、在途 `Image.onload` 置空，列入验收 |
