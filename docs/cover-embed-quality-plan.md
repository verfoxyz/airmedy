# 需求：下载时嵌入「大图封面」而不是列表缩略图

> 状态：待开工
> 范围：插件返回的封面 URL 分档 + 宿主保存链路
> 硬约束：AI 不做图形化测试；封面观感由人工确认。

---

## 1. 现状（实测）

云搜索列表用的是 100×100 缩略图，**下载时把同一个 URL 嵌进了文件**：

| 文件 | 内嵌封面 | 大小 |
|---|---|---|
| `心似烟火 - 陈壹千.flac` | PNG **100×100** | 17.4 KB |
| `雨爱 - 杨丞琳.flac` | PNG **100×100** | 29.4 KB |
| `I really ∞（翻自…） - warma.flac` | **没有内嵌图** | — |

100×100 在播放器全屏、系统媒体面板、其它播放器里都会糊；而且 100×100 的 PNG 还要 17–29 KB，
比 500×500 的 JPEG 还占地方。

**对照**：库里 `artwork/` 缓存中的旧封面是 **500×500 JPEG，39 KB**——这才是文件里该有的质量。

---

## 2. 目标

| 用途 | 尺寸 | 格式 |
|---|---|---|
| 搜索列表缩略图 | 100×100 | 保持现状（浏览器按需加载） |
| **下载嵌入 / 库内封面** | **500×500**（有原图更好） | **JPEG** |

---

## 3. 方案

### 3.1 契约：封面分两档（推荐）

插件行里增加一个字段：

```
cover_url       100×100，列表用（已有）
cover_url_large 500×500 或原图，保存/嵌入用（新增）
```

- 宿主侧 `CatalogSearchResult` 同步加字段，DTO 透传；
- 前端保存时优先传 `cover_url_large`，没有则回落 `cover_url`；
- 宿主不改写 URL、不猜尺寸——尺寸规则属于插件（平台参数各不相同）。

### 3.2 备选：宿主改写尺寸参数（更快，但脆弱）

保存时把 URL 里的 `param=100y100` 替换为 `param=500y500`。
半天可上线，但依赖"URL 里一定有这个参数"，换平台就失效，**不建议作为长期方案**。

### 3.3 嵌入格式

- 目标图是 JPEG（网易云 CDN 默认返回 JPEG）；
- 若原图是 PNG（含透明），保持 PNG，不做二次压缩以免破坏画质；
- 不需要在宿主里重新编码图片——**直接取大图原字节写入**即可（现有 `attachCover` 已是这个行为）。

---

## 4. 验收

**自动**

- 插件测试：返回 `cover_url` 与 `cover_url_large` 两个字段，后者带 500 尺寸参数；
- 宿主契约测试：保存时使用 `cover_url_large`；
- 前端 store 测试：优先大图、缺失时回落缩略图。

**人工（由人做，AI 不做）**

1. 新下载一首歌 → 用 `ffprobe -select_streams v` 看内嵌图为 **500×500**；
2. 文件体积增量应在 30–60 KB 量级，不是几百 KB；
3. 全屏播放器里的封面清晰，不糊。

**只读校验**

```bash
ffprobe -v error -select_streams v -show_entries stream=codec_name,width,height \
  -of default=nw=1 "<file>"
```

---

## 5. 边界

- **已经下载过的曲目不会自动换图**，需要重新下载；批量补图这个动作不在本轮范围。
- 老下载里"没有内嵌图但软件里有封面"的情况，是库里旧行的 artwork 缓存（500×500 JPEG），
  与文件无关——这也是为什么**显示与文件必须统一来源**，否则换播放器就丢封面。

---

**0.5 天**（插件加一个字段 + 宿主契约与 DTO + 前端优先取大图 + 测试）。
