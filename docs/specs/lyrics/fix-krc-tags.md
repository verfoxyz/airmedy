# Bug：酷我 KRC 歌词显示错乱（标签漏进文本）

> 状态：待开工
> 现象：`HIT THE JACKPOT! (Hakari Dance)` 歌词显示乱（标签/文字混在一起）
> 范围：前端歌词解析；不改歌词抓取

---

## 1. 数据

库里这首歌有两份歌词：

| 来源 | 内容示例 |
|---|---|
| `tx` | `[00:04.102]Hook`（标准 LRC，正常） |
| `kw` | `[00:04.102]<520,-520>Hook`、`<3040,-3040>Hold<5960,4680>…`（酷我 **KRC** 逐字格式） |

播放的是 `kw` 那条时，歌词乱。

## 2. 根因

`frontend/src/composables/useLyrics.ts` 只支持增强 LRC 的逐字标签：

```ts
const WORD_PATTERN = /^<(\d+):([0-5]\d(?:\.\d{1,3})?)>$/
const INLINE_TAG = /<\d+:[^<>]*>/g
```

即 `<mm:ss.xx>` 形式。而 KRC 是 **`<毫秒偏移, 时长毫秒>`**（如 `<520,-520>`、`<5960,4680>`）：

- `WORD_PATTERN` 不匹配 → 逐字解析失败；
- `INLINE_TAG` 也匹配不到（没有冒号）→ **标签原样留在文本里** → 显示错乱。

## 3. 修法

在 `useLyrics.ts` 增加 KRC 支持：

1. **识别**：时间戳之后的行内标签形如 `<数字,数字>`；
2. **解析**：
   - `word.start = lineTime + offsetMs / 1000`；
   - `durationMs > 0` → `word.end = word.start + durationMs / 1000`；
   - `durationMs <= 0`（KRC 里常见负数）→ 用下一个标签的 start 作为 end，末词用行结束（下一行时间或 +1s）；
3. **兜底**：任何情况下都不把标签显示出来——`cleanText`/`INLINE_TAG` 同时匹配 `<mm:ss.xx>` 与 `<ms,ms>`；
4. 纯文本/标准 LRC 行为不变。

### 3.1 可选：来源优先级

- 若同一首歌有多份歌词，优先标准 LRC（不含 KRC 标记）用于纯文本显示；
- 仅作为兜底，不强制改抓取逻辑。

## 4. 测试

**前端**

- KRC 行：`[00:04.102]<520,-520>Hook` → 文本 `Hook`，不残留标签；
- 多词行：`<3040,-3040>Hold<5960,4680> up` → 两个词，时间递增；
- 负数时长用下一标签/行尾兜底；
- `cleanText` 同时去掉 `<mm:ss.xx>` 与 `<ms,ms>`；
- 标准 LRC、纯文本、双语歌词回归不变。

**人工**

1. 播放 `HIT THE JACKPOT! (Hakari Dance)`（kw 版本）→ 歌词正常、逐字高亮可用；
2. 标准 LRC 曲目无变化；
3. 无逐字标签的歌词正常。

## 5. 验收

- 自动：§4 全绿；
- 人工：§4 三条成立；
- 任何格式的歌词都不再显示原始标签。

## 6. 风险

- KRC 的 offset 是相对行时间还是绝对时间需按抓取内容确认（示例 `<520,-520>` 相对行更合理）；
- 不同源的 KRC 变体（`[start,dur]` 方括号/百分号）需要容错，解析失败时走纯文本兜底而不是报错。
