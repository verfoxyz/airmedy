# 任务：不喜欢确认流程统一 + 开关开启二次确认

> 状态：待开工
> 目的：每次「不喜欢」都先确认；打开「同时删除文件」开关本身也要确认
> 关联：`dislike-purge-files.md`、`dislike-purge.md`、`fix-dislike-remote-purge.md`

---

## 1. 行为

### 1.1 标记不喜欢：始终弹确认框

无论开关开/关，点「不喜欢此曲 / 不喜欢此艺人」都先弹确认弹窗：

| 开关状态 | 弹窗内容 | 按钮 |
|---|---|---|
| 关闭 | 「标记为不喜欢？只会从推荐中隐藏，不会删除任何文件。」 | 「确认标记」 / 「取消」 |
| 开启 | 「标记为不喜欢？将同时删除本地音频、封面、流缓存与歌词，且不可恢复。」+ 将删除数量 | 「删除并标记」 / 「仅标记」 / 「取消」 |

- 开关关闭时，“仅标记”就是唯一标记方式，不再有删除选项；
- 开关开启时，仍保留「仅标记」作为退路；
- 艺人级：勾选「我了解将删除 N 首」后「删除并标记」才可点。

### 1.2 打开开关：二次确认

- 在设置页把开关从关→开时，弹确认：
  - 「开启后，标记不喜欢会删除本地音频、封面、流缓存和歌词，且不可恢复。确定开启？」
  - 「开启」 / 「取消」；
- 取消 → 开关保持关闭、不保存；
- 关闭开关不需要确认（立即生效）。

## 2. 实现

- `dislikeStore.requestDislike`：不再根据开关短路，始终 `pending = request` 并打开弹窗；
- 弹窗根据 `appStore.dislikePurgeFiles` 切换文案与按钮组；
- 开关：`DislikeSettings.setPurge(true)` 先打开一个 `ConfirmDialog`，确认后再调用 `updateDislikePurgeFiles(true)`；关闭直接调用；
- 文案复用/新增 i18n（12 语言）：
  - `settings.dislike_mark_confirm_title/body`
  - `settings.dislike_purge_confirm_title/body`
  - `settings.dislike_enable_purge_title/body`
  - `common.confirm/cancel`

## 3. 测试

**前端**

- 开关关闭时点不喜欢 → 弹窗出现，仅有「确认标记 / 取消」；
- 开关打开时 → 弹窗出现，展示删除数量与三个按钮；
- 打开开关 → 二次确认出现；取消后值仍为 false、不调用保存；
- 艺人级勾选逻辑保持；
- 12 语言键齐全。

**人工**

1. 关闭开关 → 点不喜欢 → 弹窗 → 确认后只隐藏；
2. 打开开关 → 立即弹二次确认 → 确认后开关为开；
3. 再次点不喜欢 → 弹窗提示删除数量 → 「仅标记」不删文件、「删除并标记」删除。

## 4. 验收

- 所有不喜欢操作都经过确认；
- 开关开启有二次确认；
- 两种模式的行为与文案匹配。

## 5. 风险

- 弹窗增多会影响连续标记效率（可接受，删除不可逆）；
- 开关二次确认的取消必须不写库，注意不要先乐观更新。
