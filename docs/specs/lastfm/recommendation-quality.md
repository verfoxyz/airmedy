# 任务：提升个性化推荐质量（本地种子 + 电台模式 + 多样性）

> 状态：待开工
> 背景：现有推荐只用 Last.fm 的 `topTracks` 做种子；本地导入的歌大多没有 scrobble，导致推荐只围绕少数几首、且重复
> 关联：`discovery.md`（发现列表）、`recommendation-lists.md`、`player/`（队列）、`media-request-state-machine.md`

---

## 阶段 1：种子加“本地听歌历史”（A）

### 1.1 种子来源（合并去重）

| 来源 | 数据 | 权重 |
|---|---|---|
| 本地听歌统计 | `daily_track_listening_stats`（最近 90 天，`listened_seconds` 排序） | 1.0 |
| 本地播放次数 | `tracks.play_count` | 0.9 |
| 本地收藏/歌单常听 | 歌单内曲目的播放加权 | 0.7 |
| Last.fm 常听曲目 | `user.getTopTracks(overall)` | 0.6 |
| Last.fm 常听艺人 | `user.getTopArtists(6month)` | 0.5 |

- 曲目种子按 `artist + title` 归一化去重；
- 艺人种子按 `ArtistSetKey` 去重；
- 最终取 **10 个曲目种子 + 10 个艺人种子**；
- 本地数据优先：有本地历史时，Last.fm 种子占比不超过 40%。

### 1.2 稳定性

- 按 ISO 周缓存种子（同一周内推荐结果稳定）；
- 每周轮换：上周种子与新种子各占一半（避免突变）。

### 1.3 冷启动

- 没有任何本地历史和 Last.fm 账号：用 `chart.getTopTracks` + 曲库高频标签兜底，并标注“通用推荐”。

## 阶段 2：电台模式（C）

### 2.1 入口

- 曲目右键菜单：「开始电台」；
- 详情页 / 搜索结果：播放按钮旁的「电台」；
- Last.fm「发现」卡片：「以此歌单开始电台」。

### 2.2 行为

- 从当前曲目/歌单出发，构建队列：
  1. 首批 20 首：`track.getSimilar` → 相似艺人热曲 → 标签兜底；
  2. 队列剩余不足 5 首时自动补充 10 首（后台，不阻塞播放）；
  3. 过滤：本地已有、最近 30 天听过、当前队列重复；
  4. 只追加匹配到可播源的曲目；
  5. 每补充一批使用新种子（当前播放曲目），避免整队都是一首歌的邻居。
- 电台模式在顶部显示标记（可关闭，关闭后不再自动补充）；
- 切歌不影响模式；切换普通播放/清空队列时退出电台。

### 2.3 队列防抖

- 补充任务单飞（同一时间只有一个）；
- 补充失败只重试一次，然后保留现有队列。

## 阶段 3：多样性约束（D）

对「发现」「电台」同时生效：

- 同一艺人最多 **2 首**；
- 同一专辑最多 **1 首**；
- 前 10 首里至少 **3 个不同艺人**；
- 连续两首不来自同一艺人；
- 若过滤后不足，按优先级放宽：先放宽专辑，再放宽艺人。

## 数据与实现

- 新增 `RecommendationSeedSource`（本地统计查询 + Last.fm），返回统一 `Seed` 结构；
- 新增 `RadioSession`（内存态 + 最近补充时间），不持久化队列，重启即结束；
- 推荐候选与现有 discovery 共用匹配队列和持久化列表；
- 事件：`radio:queue-appended`（前端提示「已补充 N 首」）。

## 测试

**Go**

- 种子合并权重与本地优先（本地占比 > 60%）；
- 周缓存稳定、跨周轮换；
- 电台：首批 20 首、不足补充、过滤近期听过、单飞补充；
- 多样性：艺人/专辑上限、连续同类限制、放宽顺序；
- 冷启动无数据兜底。

**前端**

- 电台入口与标记显示；
- 队列补充提示；
- 关闭电台后不再补充。

**人工**

1. 播放本地导入曲目（无 scrobble）→ 开始电台 → 推荐明显贴近口味；
2. 连续听 10 首 → 队列自动补充且不重复；
3. 「发现」里艺人/专辑不扎堆；
4. 一周后种子轮换，推荐不完全相同。

## 验收

- 自动：测试全绿；
- 人工：上述四条成立；
- 本地导入用户的推荐不再只围绕 1–2 首歌。

## 风险

- 本地统计稀疏（新库）时权重会退化到 Last.fm；
- 电台自动补充会产生额外 Last.fm 请求与源匹配，需要限流与缓存；
- 多样性过滤可能让候选不足，必须允许逐级放宽。
