# Bug：进入 Last.fm 页后首次悬停歌单卡片，按钮会“回弹”一次

> 状态：✅ 已完成（采用 §3.2：卡片首次挂载/KeepAlive 重新激活后的前两帧禁用过渡）
> 现象：从其它页面切到 Last.fm，把鼠标悬停在歌单卡片上，操作按钮先出现、缩回、再出现一次

---

## 1. 现象

- 只在**进入页面后的第一次悬停**出现；
- 之后悬停正常，不再回弹；
- 切到别的页面再回来可以复现。

## 2. 原因

卡片的悬停效果是纯 CSS 过渡：

```
遮盖层 opacity-0 → group-hover:opacity-100
按钮   translate-y-4 → group-hover:translate-y-0
```

问题在于**元素在鼠标已经悬停时被挂载/重新挂载**：

1. 页面先渲染骨架屏（`v-else-if="loading && !collection"`）；
2. 数据到达后骨架屏被替换成 `VirtualizedGrid` 卡片，此时鼠标已经在卡片区域上；
3. 新卡片的按钮从初始状态（`translate-y-4 / opacity-0`）过渡到悬停态，transition 重新播放；
4. `VirtualizedGrid` 挂载后还会做一次尺寸测量/行重排，可能再触发一次重渲染；
5. 于是视觉上就是“出现 → 缩回 → 再出现”。

## 3. 修法

### 3.1 避免“悬停中挂载”

- 进入页面时**先渲染卡片骨架**（与真实卡片同样尺寸、同样的 DOM 结构），数据到达只替换内容，不替换容器；
- 或者骨架屏与卡片网格使用同一个容器，`v-show` 而不是 `v-if` 切换，避免 DOM 重建。

### 3.2 首次挂载禁用过渡

- 卡片根元素挂载后加一个 `no-transition` 类（`transition: none`），
  在 `requestAnimationFrame` + 一个 tick 后移除；
- 这样即使鼠标已在上面，也不会播放入场过渡。

### 3.3 稳定 key 与虚拟列表

- 卡片 key 固定为 `kind`；
- `VirtualizedGrid` 的 items 引用在数据事件更新时尽量复用（避免整组替换）；
- 测量后的重排不应导致卡片内部按钮重新挂载（外层滚动容器尺寸变化时保持子节点）。

## 4. 测试

**前端**

- 首次挂载的卡片带 `no-transition`，下一帧后移除；
- 骨架 → 数据切换不会重建卡片 DOM（快照/挂载计数）；
- 悬停状态在数据更新后保持（按钮不回到初始位置）。

**人工**

1. 从其它页面切到 Last.fm，立即悬停卡片 → 按钮只出现一次，不回弹；
2. 单卡刷新、匹配事件到达时，悬停状态不闪；
3. 反复切换页面仍正常。

## 5. 验收

- 自动：§4 全绿；
- 人工：§4 三条成立。

## 6. 风险

- 禁用过渡要控制在一帧内，否则会影响正常悬停动画；
- 虚拟列表在首帧测量时仍可能重排，需确认不重建卡片内部节点。
