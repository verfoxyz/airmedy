# 任务：Last.fm 列表行补齐常用右键菜单

> 状态：待开工
> 目的：Last.fm 推荐行现在只有“刷新此曲的源 / 不喜欢”，缺少播放、队列、歌单、保存等常用操作
> 关联：`recommendation-lists.md`、`dislike-tag.md`、`recommendation-quality.md`（电台）

---

## 1. 现状

行菜单只有三项：

- 刷新此曲的源
- 不喜欢此曲
- 不喜欢此艺人

而本地曲目行（`TrackTable`）已有播放、下一首、队列、歌单、收藏等一整套操作。

## 2. 目标菜单（顺序固定）

| 分组 | 菜单项 | 可用条件 |
|---|---|---|
| 播放 | 播放 | 行可播（有 provider 或本地命中，非 matching） |
| 播放 | 下一首播放 | 同上 |
| 播放 | 添加到队列 | 同上 |
| 播放 | 开始电台（以此曲为种子） | 同上 |
| 收藏 | 添加到歌单 ▸ | 同上 |
| 收藏 | 保存到资料库 | 未在库中（remote/matching 之外的匹配行） |
| 收藏 | 收藏（已在库中时） | 已匹配到本地行 |
| 信息 | 打开艺人 / 打开专辑 | 已匹配到本地行或已入库 |
| 信息 | 复制「艺人 - 标题」 | 总是可用 |
| Last.fm | 刷新此曲的源 | 非 matching |
| Last.fm | 不喜欢此曲 | 总是可用 |
| Last.fm | 不喜欢此艺人 | 艺术家名非空 |

- 「保存到资料库」= upsert 媒体请求（`desired=promote`，无缓存则下载），复用现有 saver；
- 「收藏」只在已匹配本地行时出现，调用现有的收藏切换；
- 「开始电台」复用 `radio` 的以曲目为种子入口；
- 不可用项**置灰**而不是隐藏，避免菜单顺序跳动。

## 3. 实现

- 新增 `useLastFmRowMenu(item)`（composable），输出菜单项数组；
- 复用现有 `ContextMenu` / `rowMenu` 组件；
- 动作：
  - 播放/队列：`preparePlayback(row)` → `playTrackIds` / `playNext` / `appendToQueue`；
  - 歌单：打开现有「添加到歌单」弹窗，传入解析后的 track；
  - 保存：调用 `dislikeStore` 同级的媒体请求 store 或 `catalog` 保存入口；
  - 电台：`lastfmRadio.startFromTrack(trackId)`；
- 行未匹配时：播放类菜单置灰，并在 tooltip/提示中说明「匹配中」。

## 4. 测试

**前端**

- 菜单项顺序与分组；
- 未匹配行：播放/队列/歌单/保存置灰，刷新/不喜欢/复制可用；
- 已匹配行：全部可用，动作调用正确 store 方法；
- 已入库行：显示「收藏」而不是「保存到资料库」；
- 右键菜单在列表与详情页行为一致。

**人工**

1. 右键推荐行 → 播放/下一首/队列/歌单/电台均生效；
2. 匹配中的行 → 播放类置灰，刷新与不喜欢可用；
3. 已在库的行 → 可收藏、可跳转艺人/专辑。

## 5. 验收

- 自动：§4 全绿；
- 人工：§5 三条成立；
- 推荐行的操作能力与本地行基本一致。

## 6. 风险

- 未匹配行的动作需要先解析归属（preparePlayback），要避免重复注册 track；
- 菜单项增多后要注意手机/窄屏布局；
- 「保存到资料库」与「收藏」语义不同，需在文案上区分清楚。
