## 1. 目标

1. **流播放**：未下载的远程曲目可以直接播放（云端搜索结果、歌单里的 remote 行都可以）；
2. **全部缓存**：播放过的流数据留在本地临时缓存，重播/断网后不用重新拉；
3. **提升**：加入歌单或收藏时，把曲目补全为完整文件并入库，之后按本地曲目处理；
4. 临时缓存有上限，可在设置中调整；永久文件独立存放、不参与缓存淘汰。

不在范围：HLS/分片流、FFmpeg 直连 https、并发多路流、离线模式、跨设备同步。

---

## 2. 架构

```
播放器 ──http://127.0.0.1:<port>/stream/<session>──▶ StreamCache 代理 ──https──▶ 远端 URL
                                                        │
                                                        ├─ 写临时缓存文件
                                                        └─ 记录完整度 / 播放进度
```

- **FFmpeg**：只负责解码本地 http 流；启动时调用一次 `avformat_network_init()`，并设置 `rw_timeout` 与中断回调；
- **StreamCache 代理**：为一次播放建 session；转发 Range 请求；把收到的字节写入临时缓存；读取阻塞直到有数据（避免“增长文件撞 EOF”）；
- **远端 TLS / 重定向 / 重试**：全部在 Go 侧；
- **提升**：缓存完整后，复用下载管线的“落库”步骤（标签、封面、歌词、与 remote 行合并），不重新下载。

### 2.1 代理接口（草案）

- `GET /stream/<session>`，支持单段 `Range: bytes=N-`；
- 响应：`200` 或 `206`，带 `Content-Type`、`Content-Length`（已知时）、`Accept-Ranges: bytes`；
- 读超时/上游失败：连接断开，播放器按“失败 → 提示重试”处理；
- session 生命周期 = 一次播放；停止/切歌即关闭，临时文件保留在缓存里；
- **启动预缓冲**：`Open` 返回本地 URL 之前，等待已下载字节达到阈值（默认约 1 MB 或 3 秒音频，取先到者）或超时（默认 10 秒）；否则解码器的第一次读会直接阻塞在代理上。

## 3. 已确定的决策

| 项 | 决定 |
|---|---|
| 提升触发 | **加入歌单**、**收藏（红心）** 都触发后台提升 |
| 提升时机 | 允许播放中提升 → **延迟提升**：先标记，播放结束（或切走）后补全、移动、入库 |
| 临时缓存上限 | **可在设置中调整**，默认 2 GB |
| 永久文件 | 独立目录、不设上限、不参与缓存淘汰 |
| 淘汰顺序 | 先删**完整度最低**的，再删**播放进度最低**的 |
| 并发 | 暂按**单路流**设计 |
| 失败处理 | **提示重试**，不自动下载、不自动换源 |
| 播放入口 | 搜索结果 + 歌单中的未下载曲目 |
| 音质 | **设置内全局选择**，默认 320k，透传给 `stream.resolve` |
| 音质优先级 | `128k` < `320k` < `flac`（未知视为最低） |
| 音质与提升 | 见 §4.4：缓存音质 ≥ 下载音质 → 直接提升；下载音质更高 → 按下载音质重拉并删除旧缓存 |

## 4. 后端改动

### 4.1 FFmpeg / 解码器

- 初始化时调用 `avformat_network_init()`；
- 给 `AVFormatContext` 设置 `rw_timeout` 与 `interrupt_callback`（停止/切歌能立刻中断）；
- 无需 TLS（本地代理是 http）。

### 4.2 StreamCache 服务（新增）

- 缓存目录：`<DataDir>/stream-cache/` 只放音频文件 `<key>.audio`；元数据（identity、title/artist、时长、字节数、进度、待提升标记）存在主库 `stream_cache` 表（见 [`task-cache-db.md`](task-cache-db.md)）；
- **会话**：播放时创建，返回本地 URL；同 identity 重播直接命中已有缓存；
- **下载**：Range 续传、失败重试（有限次）、超时；写文件后更新元数据；
- **读**：若请求的字节还没下载到，阻塞等待（代理内部可轮询/条件变量）；
- **淘汰**：`SUM(size) > 上限` 时按 §3 顺序删除，跳过正在播放的 session 和待提升条目；
- **提升**：`Promote(identity)` → 标记 pending；完整后把文件交给下载管线的落库步骤；
- **预缓冲**：返回 URL 前等待一个安全水位，避免播放刚开始就因代理阻塞而无数据（见 §2.1）。

### 4.3 播放器

- 远程曲目加载前调用 `domain.StreamResolver`（现有 `PluginResolver`）拿 URL；
- URL 交给 StreamCache 建 session，再把本地 URL 传给音频后端；
- URL 过期/播放中断：按“提示重试”处理（不自动换源）；
- 队列/状态：remote 行已经能恢复，恢复后播放同样走解析；
- 播放进度变化时同步给 StreamCache（用于淘汰规则）；
- scrobble / now playing 对 remote 曲目同样生效；
- 歌词：本阶段不额外处理（保持现有降级行为）；
- 封面：`currentTrack` 是远程行时，用该 identity 最近一次搜索记下的 `cover_url`（宿主 `rememberCovers` / `cover-cache`），播放器状态里下发本地 URL，供歌曲信息与迷你播放器渲染。

### 4.4 提升管线

1. 加入歌单 / 收藏 → 若曲目是 remote 且未提升 → **立即在 `stream_cache` 落一条持久任务**（`pending_promote = 1`），此时不动任何文件；应用中途关闭也不会丢；
2. 只有该曲目**没有活动 session**（播放结束 / 切歌 / 从未播放）时才执行——因为提升是**移动**缓存文件，播放中移动会让解码器读不到数据；
3. 执行前若缓存未完整，先补全（Range 续传）；
4. 完整后按**音质**决定：

   | 缓存音质 vs 下载设置 | 动作 |
   |---|---|
   | 相同 | 直接提升（移动缓存文件） |
   | 缓存更高（如缓存 flac、下载设置 320k） | 直接提升，保留高音质文件 |
   | 下载设置更高（如缓存 320k、下载设置 flac） | **按下载音质重新拉取**，成功后删除旧缓存（音频 + 表行），再入库 |
   | 缓存音质未知 | 视为最低 → 下载设置更高时重拉；否则直接提升 |

5. 复用下载管线：写标签、封面、歌词、与 remote 行合并，歌单条目改指本地曲目；
6. **移动成功之后**才删除缓存条目（音频 + `stream_cache` 行）；失败保留任务，稍后重试。

> 执行者：新增一个提升 worker（`app/download` 或独立服务）。触发时机：启动时扫描、每 30 秒巡检、以及 session 关闭事件。扫描条件是 `pending_promote = 1` 且该 identity 没有活动 session。
>
> “重新拉取”走普通下载流程（`stream.resolve` 指定下载音质），不复用缓存文件；缓存条目在下载成功后删除。

### 4.5 封面缓存与音乐缓存的关联

封面缓存（`cover_cache`，按 URL hash）和音乐缓存（`stream-cache`，按 identity）目前互不知情。目标：**被音乐缓存引用的封面活得更久**。

1. **建关联**：迁移 `000091` 给 `cover_cache` 增加 `provider`、`external_id` 两列（可为空）；`GetCatalogCovers` 的请求本来就带 identity，写入时一并记录；
2. **打标**：StreamCache 在 session 创建/下载完成时，把该 identity 的封面标记为“被引用”；session 被淘汰/删除时解除；
3. **分层淘汰**：封面超限时先删**未被引用**的（按 `last_used`），再删被引用的（同样按 `last_used`）；
4. **边界**：合并后的一个封面可能对应多个 identity（多源同一首），只要任一 identity 有音乐缓存就算被引用；
5. **降级**：关联列缺失或 identity 未知时，按原来的纯 LRU 处理。

### 4.6 设置

| key | 默认 | 范围 | 说明 |
|---|---|---|---|
| `stream_cache_mb` | 2048 | 256–20480 | 临时缓存上限 |
| `stream_quality` | `320k` | 由插件支持值决定 | 透传 `stream.resolve` |

设置项需要 12 个语言文件同步（`AGENTS.md` §2.1）。

**Go**

- 代理：Range 解析、206 响应、阻塞读、上游重试、session 关闭；
- 缓存：完整度/播放进度淘汰顺序、上限钳制、正在播放条目不被删；
- 提升：未完整时不移动、完整后走落库、播放中延迟；
- 设置：默认值与范围钳制。

**前端**

- 搜索结果可播放；
- 歌单 remote 行可播放；
- 失败提示与重试；
- 设置项保存与回显。

**人工**

1. 搜一首云端歌 → 直接播放，拖动进度条正常；
2. 播放中加歌单 → 播放结束后文件出现、歌单条目变为本地；
3. 收藏一首流曲目 → 后台提升完成；
4. 重播同一首 → 命中缓存，秒开；
5. 缓存写满 → 按规则淘汰；
6. 重启应用 → 队列恢复、remote 行可继续播；
7. 断网/源失效 → 提示重试，不崩溃；
8. **限速网络**（如 128 kbps 或高延迟）下播放 320k 流：不应出现断音/爆音；若出现，按 §7 的备选方案处理并记录结论。

## 7. 风险

- **lx 源覆盖**：取决于导入脚本（当前 ikun 支持 wy/kg/kw/tx；mg 无可用脚本）→ 搜到但解析不了时要给明确提示；
- **URL 时效**：短时效地址需在失败时重新解析（由重试触发）；
- **磁盘**：临时缓存上限必须真正生效，避免无限增长；
- **格式**：直链 MP3/FLAC/AAC 可用；M4A（moov 在尾部）需验证，必要时限制或提示；
- **音频线程阻塞（M3 重点）**：FFmpeg 的解码读沿用 miniaudio 数据源回调，读操作发生在音频线程上。代理在数据未到时会阻塞等待（当前 50 ms 轮询），慢网/卡顿时可能直接造成断音。M3 接入真实流后必须实测；若出现，按顺序尝试：
  1. 提高预缓冲水位（先缓冲更多再开播）；
  2. 代理端更激进的读前取（已经边下边播，主要是起始水位）；
  3. 把 FFmpeg 解码移出音频线程（独立解码线程 + 环形缓冲），这是结构性改动，最后才做。
- **合规**：仅缓存用户主动播放的内容，不做预取/爬取；
- **音质是“请求值”而非“实测值”**：缓存表记录的是 `stream.resolve` 请求的 quality，插件实际返回的音质可能不同；提升时按记录值比较，若插件长期不守约，需要改成探测实际码率。

## 8. 后续优化（不在本期范围）

1. **音质自动降级链**（`flac → 320k → 128k`）：当前源没有指定音质时不降级，本期不做。
2. **跨源找音质**：当前源没有用户指定的音质时，自动在其它源搜索同一首歌（复用 5 源搜索 + 严格匹配规则），找到后弹窗让用户选择：
   - 从拥有该音质的源下载（可能换源）；
   - 或保持当前源（音质较低）。

   前置条件：搜索结果/`stream.resolve` 需要能声明“该曲目支持哪些音质”，目前没有这个信息，属于后期能力。
