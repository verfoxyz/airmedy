# 需求：wy 插件更名为「聚合搜索」，补封面与歌词

> 状态：待开工
> 范围：`plugins/wy`（更名 + 能力补全）、catalog 行契约（新增封面字段）、搜索结果 UI
> 硬约束：AI 不做图形化测试；搜索质量与封面观感由人工确认。

---

## 1. 命名：一个插件，多个源标签

| 对象 | 现在 | 改为 |
|---|---|---|
| 插件 id | `wy` | **保持 `wy`**（id 是数据契约，改了就丢启用状态与 KV） |
| 显示名 `name` | 网易云搜索 | **聚合搜索** |
| 源标签 | 无 | manifest 增加 `sources: ["wy"]`，以后每接一个源追加一项 |
| 设置页介绍 | 无 | 一行："聚合多个在线音乐源；当前支持 wy" |

**关键点**：**id 与显示名解耦**。id 叫 `wy` 只是历史，UI 一律显示「聚合搜索」+ 源标签；
以后加 kg 就是 `sources: ["wy","kg"]`，不需要新建插件、不需要用户重新启用。

`describe` 的返回也要带同样结构，宿主用它渲染源按钮（已有机制，扩展字段即可）：

```json
{ "sources": [{ "id": "wy", "name": "网易云", "enabled": true }] }
```

## 2. 封面

### 2.1 搜索结果的封面从哪来

wy 的搜索接口已经返回专辑封面（`album.picUrl`），但**当前插件没有返回它**，而且
宿主侧的 catalog 行契约里**根本没有封面字段**——所以现在是"想显示也显示不了"。

要做三步：

1. 插件 row 增加 `cover_url`（取 `album.picUrl`，补上缩略参数，见下）；
2. 宿主 `CatalogSearchResult` 增加 `CoverURL`，`plugin_adapter` 透传，Wails DTO 增加 `cover_url`；
3. 前端行渲染缩略图，并在保存时把 `cover_url` 回传（现在 `stores/catalog.ts` 里写死成 `''`，
   导致下载时没有封面可嵌入）。

### 2.2 显示建议：**显示，但要按缩略图处理**

**不显示的理由**：搜索结果最多 50 行，每行一张图就是 50 个额外请求；移动网络或慢网下首屏会变慢。

**显示的理由**：用户是靠封面认歌的，尤其翻唱、同名单曲——纯文本行很难扫读；而且下载后本来就要封面。

**折中方案（推荐）**：

| 措施 | 做法 |
|---|---|
| 缩略尺寸 | 用网易云自带的参数把图缩到 100×100（`?param=100y100`），单图约 5–10 KB |
| 懒加载 | `<img loading="lazy">`，只加载进入视口的行 |
| 占位 | 固定 40×40 的圆角方块 + 音符占位图，避免图片到达时布局跳动 |
| 失败回退 | `@error` 时换成占位图，不显示破图 |
| 不做的事 | 不在搜索阶段由宿主抓图；只把 URL 交给浏览器按需加载 |

按 50 行、每张 8 KB 估算，一页最多 400 KB，且大部分行在滚动前不会加载——可以接受。

### 2.3 下载时嵌入封面

保存动作把 `cover_url` 传回后，`EnqueueWithCover` → finalize 已有完整链路
（FLAC 走 `METADATA_BLOCK_PICTURE`）。这一步不需要新代码，只需要**别再传空串**。
注意：**开关只影响搜索列表的显示，不影响下载嵌入**——关掉缩略图时，保存仍应带上封面 URL。

### 2.4 开关：搜索时是否显示缩略图（插件提供）

需求：这个开关**由插件提供**，不是核心设置。

**最小实现（不依赖完整的插件设置体系）**

插件在 `describe` 里多返回一段设置声明，只有一种控件（开关）：

```json
{
  "sources": [{ "id": "wy", "name": "网易云", "enabled": true }],
  "settings": [
    {
      "key": "cover_in_results",
      "type": "switch",
      "default": true,
      "label": { "zh": "搜索结果显示封面", "en": "Show covers in results" }
    }
  ]
}
```

宿主侧三步：

1. **渲染**：设置 → 插件 → 该插件的行里，把这类开关渲染成一行 `Switch`（复用 `@airmedy/ui`）；
2. **存储**：值存该插件自己的 KV（`storage.set`），插件重启不丢；宿主不解析它的含义；
3. **传递**：宿主在发起 `catalog.search` 时把当前值作为参数带过去，例如
   `params.include_cover: true|false`；插件据此决定是否返回 `cover_url`。

**为什么不走"插件自己读 KV"**：那需要给插件开 `permissions.kv` 并自己管读写时序；
由宿主把值放进请求参数，插件无状态、行为可测。

**为什么不做完整设置体系**：`ui.settingsSchema`（见 `docs/plugin-settings-plan.md`）是一次独立工程，
本轮只需要"一个开关"，把它拆成通用能力会拖慢交付。等它落地后再把这里的声明迁过去。

**降级行为**

| 情况 | 行为 |
|---|---|
| 插件没声明 `settings` | 宿主按默认值 `true` 处理，不显示开关 |
| 开关关闭 | 插件不返回 `cover_url`；前端渲染占位图（不显示破图） |
| 开关关闭后保存 | **仍要带封面 URL**：宿主用上一次搜索缓存的值，或向插件再取一次 |
| 插件返回了 URL 但加载失败 | 前端回退占位图 |

## 3. 歌词

### 3.1 现状

- 宿主有内置歌词源（LRCLIB、酷狗），插件**不提供歌词**；
- 因此"聚合搜索"里搜到的歌，歌词要靠宿主另一次按标题+歌手反查，经常查不到（尤其日文/翻唱）。

### 3.2 方案：插件提供 `lyric.fetch`

新增能力 `lyric.fetch`，由 wy 插件实现：

```
请求：{ provider, external_id, title, artists[], album, duration }
返回：{ lyric, tlyric?, source, synced }
```

- 走网易云的歌词接口（参考 `reference/any-listen-extension-online-metadata/src/onlineResource/wy/lyric.ts`
  的 eapi 实现；注意它是 Apache-2.0，借鉴算法可以，复制代码需保留署名）；
- **必须校验时间轴**：没有 `[mm:ss]` 就当失败，不返回空歌词；
- 翻译（`tlyric`）能拿到就一并返回，拿不到留空；
- 失败要有结构化原因（`unavailable` / `rate_limited` / `auth`），复用现有错误分类。

### 3.3 宿主侧

- 增加 `lyric.fetch` 路由：先问提供该 provider 的插件，失败再回落到内置 LRCLIB；
- 结果写入 `lyrics` 表前做时间轴校验（这条本来就在为内置源做，复用即可）。

## 5. 验收

**自动**

- 插件测试：搜索返回带 `cover_url`；`include_cover: false` 时不返回封面；歌词缺失/无时间轴时返回失败而不是空串；
- 宿主测试：插件声明的开关能被读取并写入 KV；搜索时把开关值作为参数下发；
- 宿主测试：`lyric.fetch` 优先走插件、失败回落 LRCLIB；catalog 行 DTO 含封面字段；
- 前端 spec：有 `cover_url` 渲染 `<img>`、无则渲染占位、加载失败回退占位。

**人工（由人做，AI 不做）**

1. 搜索一个日文/翻唱曲目：行上有封面缩略图，滚动流畅，无布局跳动；
2. 图片加载失败的那一行显示占位图，不出现破图；
3. 关闭「搜索结果显示封面」后：列表变成占位图，但保存后下载的文件仍然带封面；
4. 保存该曲目后：下载完成的文件带封面；
5. 播放时能显示歌词，且歌词有时间轴（能滚动）。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 网易云图片有防盗链 | 先用真实 URL 验证；不行就只显示占位图，封面留给下载阶段 |
| 50 张图拖慢首屏 | 缩略参数 + `loading="lazy"`；必要时首批限 20 张 |
| eapi 加密歌词随时失效 | 失败即回落内置 LRCLIB；不把歌词做成硬依赖 |
| 契约改动波及保存路径 | `cover_url` 是新增可选字段，旧插件不返回时按空处理，不破坏现有行为 |
